# 内部试用使用说明

当前只生成内部未签名构建，未完成干净 Windows 安装或真实模型验收；不得作为正式试用包分发。现有 Claude、GPT、GLM 入口的实际可执行 provider registry 为 0；连接、额度与质量未知。下列步骤用于获批后的受控试用，不表示已经进行真实用户试用。

1. 发布负责人先核对最终候选哈希、生产发布者、干净账户安装、备份恢复及更新证据。满足这些门槛后再开始提议的 5 个工作日观察窗口。
2. 打开工作台，在独立设置页检查连接。未配置和未通过运行能力核验的入口保持待连接；本地服务健康不证明模型可调用。不要把提供商凭证粘贴到聊天。
3. 选择已核验的 A 入口，创建会话并输入完整限制。Claude 中文输入及纠正完整译英；GPT 不强制翻译。先用非敏感材料确认权限与格式能力。
4. 需要文件时明确要求格式和语言。确认英文原件由 A 完整定稿、中文译文由 B 完整翻译；在双语配对卡中逐项预览，再选择本地保存目录。未完成或 QA 拒绝的配对不得发布。
5. 取消操作需要区分本地停止与远端确认；看到待核对时保留任务记录。重启后按中文状态提示恢复，避免反复提交造成重复费用。
6. 用量页的未知值保持未知。失败、重试、翻译、审查和 A 完整定稿成本都计入总成本；本构建没有取得任何 A 质量或省 token 资格。
7. 备份与恢复按 [备份恢复手册](backup-restore-runbook.md) 操作。恢复先在隔离目录核验，保持原现场。更新先验证签名、包哈希与兼容 schema，见 [更新回滚手册](update-rollback-runbook.md)。
8. 反馈仅记录构建、场景、期望、实际、严重度和可复现步骤。独立诊断页的导出默认不包含聊天正文、附件和凭证。当前反馈导出不支持附带正文；不要把诊断当作自动上传功能。

P0：数据丢失、泄漏、错误发布；P1：核心功能阻断；P2：一般功能问题；P3：展示问题。反馈表见 feedback-schema.json，空 triage 台账不代表零缺陷或稳定。观察结束需要检查真实成果、回归与复验；日历到期不会自动放行。没有创建自动提醒、监控计划或外部消息。
