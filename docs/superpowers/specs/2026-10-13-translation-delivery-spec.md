# Claude 条件翻译与双语文件交付规格

日期：2026-10-13（Asia/Shanghai）  
状态：可实施的产品与接口规格；尚未实现，也未验证用户本机 Claude Code、ZCode 或文档处理能力。  
适用：A 默认 Claude，备选 GPT；B 为 ZCode 中的 GLM；C 为确定性调度程序。与主设计冲突时，本文件对语言路由、界面呈现及文件来源的细化优先。

## 1. 目标与不可变规则

1. 首要目标是保持 A 独立执行同类任务的质量，再减少 A 的总 token；翻译不得删减要求来节省 token。
2. A 实际使用 Claude 时，中文用户输入经 B 完整翻译为英文后交给 A；A 的英文回答经 B 完整翻译为中文后显示。
3. A 实际使用 GPT 时，不强制启用该翻译通道；中文可以直接交给 A，默认以中文回答。用户另外明确要求翻译时按该任务执行。
4. 主聊天页只呈现用户问题、最终回答、必要澄清与文件附件；不出现翻译过程、A/B 交接、检查日志或内部英文回答。
5. Claude 路径的 PDF、Word、Markdown 等文字文档按用户要求的每种格式交付两个完整文件：A 的英文定稿原件、B 的中文译文。不是仅交摘要，也不强制制作逐段混排版本。
6. 翻译是语言和体验功能；服务接入资格由提供商、账号及合法可用的接入方式决定，改变提问语言不能改变资格。本系统不实现地区限制绕过。
7. “完全正确、无歧义”是质量目标，不能作为模型零误差承诺。程序提供校验、停止和澄清机制；未达发布门槛时不伪装成功。

## 2. 依据实际模型锁定语言路由

| 属性 | 规则 |
| --- | --- |
| `provider_id` | 适配器报告实际服务提供方；不能由 App 名称推断 |
| `model_id` / `model_family` | 记录实际模型标识；`claude`、`gpt`、`glm`、`unknown` |
| `route_policy` | `claude_en_bridge`、`native`；由版本化规则计算 |
| `route_snapshot_id` | 用户一轮输入及其执行、修复、验收、输出共用不可变路由快照 |
| `identity_source` | 实际响应元数据、受支持配置或已核验适配器能力；记录核验依据 |
| `identity_status` | `verified`、`unknown`、`mismatch`；后两者禁止自动继续 |

Claude Code 接入其他模型、Codex 接入其他后端时，仍按实际 `model_family` 分流。只检测模型名含某个字符串不足以证明身份。适配器不能确认时，给出中文连接错误，不猜测其类型。

更换 A 只在下一轮生效。执行中更换账号、模型、后端或发生自动回退时，当前轮先暂停；C 建立新执行版本及新路由快照，再从已保存材料恢复。禁止中途把 GPT 内容静默按 Claude 路径处理，或省略 Claude 路径的翻译。

## 3. 输入、追问、附件和工具上下文

Claude 路径：保存中文原件 → 分块与保护标记 → B 翻成英文 → C 与 B 检查 → 冻结英文上下文 → A 处理。原始用户输入始终保留，用户看到的消息也始终是其原话。

| 上下文来源 | 路由要求 |
| --- | --- |
| 首次提问、后续追问、用户纠正 | 每轮完整翻译；保留语气强弱、范围、否定、条件、优先级和格式要求 |
| A 的必要澄清 | 英文问题经 B 翻成中文显示；用户回答再次按输入通道处理 |
| 会话历史与记忆 | 保存中英映射；给 Claude 使用经校验的英文视图及必要索引，禁止重复回译造成漂移 |
| 中文附件正文 | 解析后的自然语言块完整翻译；保留与原文页码、段落、表格单元格的映射 |
| 图片、扫描 PDF、图表中文字 | 先提取/OCR，记录置信度与位置；无法可靠识别的关键内容进入澄清或失败状态 |
| 工具输出、检索材料、错误日志 | 翻译需要给 A 阅读的自然语言；原始输出和来源引用保留为证据，不把中文工具文本绕过语言层直接注入 |
| 代码、公式、标识符和原始数据 | 保护性传递；自然语言说明可翻译，结构和可执行语义不得改写 |
| 非文本原件 | 按任务提供必要原件与英文说明；不把图片重画或更改数据当作翻译 |

全文翻译和任务上下文选择是两层不同操作。交给 B 的待译范围必须逐块覆盖；A 只读取当前任务所需部分时，C 记录材料索引及选择范围，不能把摘要标成全文译文。用户要求全文审查或全文交付时，全部相关正文、表格、脚注和附录均必须覆盖。

执行器通过上下文网关读材料。给 A 的工具工作区提供英文派生视图及原件定位；读取被保护的中文代码标识、引文或必要原始图像时允许保留原字形，并标明其证据用途。不得为“全英文”破坏代码、原始数据或引用真实性。

源材料中的指令性文本按资料处理，不提升为系统指令。翻译结果无权改变工具权限、验收标准、预算或执行范围。日志和展示层对密钥等敏感字段脱敏，但不可在用户未授权的情况下借翻译将其他任务资料带入当前上下文。

## 4. 忠实翻译协议

### 4.1 保留项

- 不概述、不发挥、不增加论据，不把建议改成命令，不把可能性改成确定性。
- 数值、正负号、比较符、比例、单位、日期、货币、置信区间和统计显著性必须保留语义；无明确要求不换算单位。
- 专名、人名、机构、产品版本、文件路径、URL、DOI、引用编号、标题层级和交叉引用必须可追踪。
- 代码块、命令、公式、变量、JSON 键、占位符等设为不可改写片段；中文用户界面字符串属于产品内容，按任务要求保留或明确本地化，不能机械英文化。
- 建立任务级术语表，同一概念一致翻译；确需一词多义时按领域与所在块记录不同义项。
- 对引文区分原文引用与译文引用，保留原始来源；不得让译文伪装成出处中的逐字原文。

### 4.2 歧义和缺失

原文有多个合理解释时保留这些解释或标为待澄清，不自行补定事实。不会影响任务的措辞差异可采用有依据的通用表达；会改变业务范围、实现行为、数字含义或论文结论的歧义必须用中文向用户提出具体问题。

附件损坏、OCR 关键字符无法确认、表格单元格无法对齐、上下文截断均为实质缺口。不能用“按常识补齐”通过检查。A 已给出的不确定性与限制在中文回答中必须保留。

### 4.3 源码和结构保护实现

采用结构化解析，不以正则替换整份文件。Markdown 按语法树分块；Word 按段落、表格、脚注、链接和图片说明提取；PDF 按可恢复阅读顺序建立块及原页定位。原始文件不可覆盖。

对受保护片段生成 `protected_span_id`、原始字节哈希及类型；B 输出同一占位标记，C 精确回填并检测丢失、重复、重排和篡改。用户原文中的相似占位字符串应转义，避免碰撞。

## 5. 翻译质量门槛与有界修复

每次翻译候选按以下顺序检查，不能仅依赖 B 宣称“准确”：

1. C 检查块覆盖率、占位完整性、非空内容、截断迹象、数字/单位/实体集合、引用与结构关系。
2. B 使用单独的校验请求对照源文和译文，输出逐块遗漏、歧义、术语、逻辑与语气问题及位置。
3. 对否定、条件、承诺、关键数字、公式说明、结论等高影响块作额外逐句核对；可用回译辅助，但不能把回译一致视为语义正确证明。
4. C 汇总结构检查与问题清单；所有强制项通过且没有未解决的实质语义问题后，冻结译文版本。

同一模型另开会话自检不等于独立模型验证。线上自动检查有遗漏风险；发布前评测须包含人工双语复核，并持续抽检新增领域样本。质量门槛为强制结构项 100% 通过、测试集已知重大语义错误为 0，不能把此结果外推为所有未来文本零错误。

单个翻译作业最多 3 次候选尝试，即初次生成加 2 次定点修复；每次保存差异与诊断。校验调用计入 B 用量和该轮预算。连接层重试单独计数，最多 3 次且先确认上一调用状态，避免重复执行。

超过上限后：输入翻译失败则不调用 A；输出翻译失败则保存 A 英文原件但不向主聊天页发布成功回答；文件翻译失败则不发布完成的双语附件包。呈现中文失败说明、必要澄清或重试入口。显式重试创建新的有界作业，不能后台无限循环。

A 默认不承担逐句翻译和重复翻译审查。若任务本身要求 A 判断原始关键证据，允许其进行必要事实审查；这种成本记录为 A 审核，不把全部翻译返工升级给 A 以掩盖 B 的失败。

## 6. 英文原件来源与 A 的成本

用户要求“A 给出的原文档”，因此默认 `require_a_authored_canonical=true`：A 必须实际生成或完整输出最后采用的英文正文，形成可追踪的定稿内容。B 可以提供资料和草稿；仅由 B 写全文、A 返回 `PASS` 的文件只能标为“B 撰写、A 审核”，不能称为“A 原文档”。

分别记录 `origin_authors`、`canonical_issued_by`、`reviewed_by` 与 `rendered_by`。A 基于 B 草稿输出最终完整版本时，保留 B 草稿依赖和 A 定稿响应证据；不能抹除来源历史。模型输出被截断时不得创建定稿。

A 生成英文结构化正文/Markdown，C 用确定性渲染器输出 Word/PDF 是允许的：内容来源是 A，格式渲染来源是 C。B 对 A 正文仅可做有记录且可验证的不改变内容的格式整理；正文实质变更需要重新形成 A 定稿版本。

默认双语文件路径会增加 A 生成完整英文定稿的必要输出量。节省来自资料整理、执行、翻译、检查和排版外包，不能通过虚构作者来源降低指标。未来若用户明确允许“B 撰写、A 审核”，可增加另一文档模式，但不能静默替换当前要求。

## 7. 双语文件制作与原子发布

1. A 完成英文定稿，C 保存不可变内容快照及 SHA-256 哈希，绑定任务书和 A 验收版本。
2. C 将正文解析成具有稳定 `block_id` 的文档模型；结构包含标题、段落、列表、表格、图注、脚注、参考文献和链接。
3. B 逐块翻译，输出源块到目标块的映射；禁止省略附录、表格内容或图内必要文字。无需翻译的代码、公式、文献原题明确标记保留原因。
4. C 将英文与中文内容分别渲染为每种要求的格式，并检查链接、目录、表格、字体、图片、公式及分页。
5. 两种语言允许重新分页，不要求页数一致；保留章节与块映射，不使用同页码假定建立中英对应。PDF/Word 必须渲染并查看关键页和高风险页面；OCR 来源另核对原始图像。
6. 完成内容检查、版面检查、哈希复核后，C 在同一数据库事务内发布文件配对及聊天回答；文件先写入临时目录，完整后以不可变路径入库。发布事件只指向完整文件。

文件示例：`report.v3.en.pdf` 与 `report.v3.zh-CN.pdf`；用户同时要求 Word 和 PDF 时发布两个语言各两种格式。Markdown 交付需包含或可访问所引用资源，并验证相对链接。

任一英文原件发生实质修改，相关中文译文、排版结果、QA 与发布资格立即失效；按依赖关系重新翻译受影响块，并复验跨块引用与全篇一致性。原件不得原地覆盖；旧版配对保留为历史，不显示为最新版。

只有整个请求所需的英文原件、中文译文及校验结果均就绪，才标记 `PUBLISHED`。下载链接、重连消息与缓存同样按 `bundle_id` 和版本读取，避免出现 v3 英文配 v2 中文。发送失败可以幂等重发同一配对，不重新调用 A。

编程任务的可执行源码和数据文件按任务原语义交付；随附 README、使用说明、报告等文字文档适用双语规则。不能翻译变量名或代码字符串导致程序行为变化。

## 8. 数据契约

| 记录 | 必需字段 |
| --- | --- |
| `RouteSnapshot` | `id, task_id, turn_id, attempt_id, provider_id, model_id, model_family, adapter_id, identity_status, identity_source, connection_version, policy_version, route_policy, locked_at` |
| `MessageRecord` | `id, turn_id, source_role, language, raw_content_ref, content_sha256, parent_message_id, route_snapshot_id, visibility, created_at` |
| `TranslationJob` | `id, task_id, turn_id, source_ref, source_sha256, source_language, target_language, glossary_version, policy_version, purpose, status, attempt_count, budget_id` |
| `TranslationBlock` | `job_id, block_id, source_locator, source_sha256, target_ref, target_sha256, protected_span_ids, translation_status, uncertainty_codes` |
| `TranslationQA` | `id, job_id, candidate_version, coverage_result, protected_span_result, numeric_entity_result, semantic_findings, severity, verifier_model, check_version, evidence_ref` |
| `ArtifactVersion` | `id, task_id, artifact_kind, language, immutable_uri, byte_sha256, canonical_content_sha256, source_version_id, origin_authors, canonical_issued_by, reviewed_by, rendered_by, a_response_ref, dependencies` |
| `DeliveryBundle` | `id, task_id, turn_id, spec_version, route_snapshot_id, source_version_ids, translation_version_ids, format_pairs, qa_ids, approval_id, state, published_at` |

`visibility` 仅允许 `user`、`internal`、`attachment`。内部英文回答不会经普通聊天 API、实时推送或 HTML 调试字段泄露到主页面；英文原文档通过附件区域有意提供。

翻译作业状态：`PENDING → RUNNING → QA → READY`；分支为 `REPAIRING, NEEDS_INPUT, FAILED, CANCELLED, STALE`。交付包状态：`STAGING → VERIFIED → PUBLISHED`；失败或旧版本不可进入 `PUBLISHED`。

缓存键至少包含源内容哈希、语言方向、术语表版本、翻译策略版本、译者模型版本及必要上下文哈希。同文不同语境不得误用缓存。缓存命中仍核对保护片段和依赖版本；token 用量区分真实供应商报告、不可得值和估算值。

`DeliveryBundle.format_pairs` 每项明确包含 `artifact_pair_id, format, source_version_id, english_artifact_id, chinese_artifact_id`。界面按该配对记录取文件，不以相似文件名推断配对。

## 9. 界面行为

- 常规聊天：中文问题 → 通用等待状态 → 中文最终回答；等待状态不显示“A 规划/B 翻译”等过程。允许取消和重试。
- 澄清：以中文回答气泡呈现一个具体问题；不显示内部失败链或模型之间的争论。
- 文档：中文最终回答下显示“英文原件”“中文译文”两个附件入口；各格式成对展示，文件名、版本和大小可识别。
- 错误：例如“这次回答未能完成，已保存当前进度。请重试。”；不要暴露后台处理阶段、密钥、完整日志或错误原文。
- 日志、用量和模型配置放在独立设置/诊断区，默认不进入聊天消息；诊断访问也应遵循本地数据权限。
- GPT 模式：默认直接显示中文回答，附件按用户所需语言交付；不强制另造英文版或增加 B 翻译调用。

## 10. 关键验收案例

| 编号 | 输入/故障 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | Claude，中文问题含否定、条件、优先级 | A 收到完整英文等义请求；页面保留原中文；没有遗漏限定 |
| T02 | GPT，中文提问 | 无强制翻译作业；问题直接进入 A；中文回答正常呈现 |
| T03 | 同名 App 更换实际后端 | 路由以已核验模型身份为准；身份未知/不匹配时中文报错并停止 |
| T04 | 运行中模型回退或用户切换 A | 当前路由不变更；暂停并建立新版本后恢复，不混用路由 |
| T05 | A 英文澄清，用户中文补充 | 只显示中文问题与中文回复；补充经过输入通道，先前约束完整保留 |
| T06 | 代码、路径、公式、DOI、数字与自然语言混合 | 可执行片段及引用保持完整；自然语言忠实翻译；保护标记不出现在成品 |
| T07 | 论文有脚注、表格、图注、附录及中文来源 | 完整块覆盖、双向定位、引文不捏造；不能把摘要当完整文件 |
| T08 | 输入存在会改变需求的两种解释 | 生成中文必要澄清，未擅自选义、未先让 A 按猜测执行 |
| T09 | 第 3 次输入翻译仍失败 | 不调用 A，中文失败说明；失败尝试及 B 用量可追踪 |
| T10 | A 已完成，但输出翻译失败 | 英文内部稿保存；没有成功中文气泡或已完成标记；有限重试可恢复 |
| T11 | 两份文档之一渲染失败、服务崩溃或下载重试 | 不出现半个成功配对；恢复后同一版本原子发布，幂等且不重复调用 A |
| T12 | 原件 v3 修改后仍有 v2 译文缓存 | 旧译文标记失效；不发布 v3/v2 配对；重译并复验依赖 |
| T13 | B 写全文，A 只给 PASS | 不能标为 A 原文档；严格模式要求补齐 A 实际定稿，保留真实来源 |
