## 不可变规则

1. 质量优先级为 A 独立完成同类任务的质量 → 尽量减少 A 总 token → 在前两项允许的范围内优化耗时和 B 用量。保持正确性、约束完整性、核心推理、证据、整体一致性和最终可用性；禁止降低到基线质量的 95%。QA-01 的 95% 只表示统计置信水平，资格要求配对差值单侧置信下界 ≥ 0 且无新增关键缺陷。
2. A 保留问题建模、核心推理、方法/架构/论证选择、关键证据判断和最终验收。普通、关键节点指导、A 主导三种执行深度可升级。两次参与只适用于简单路径，不是固定阶段或底层请求次数上限；完整审稿及困难推理的必要成本保留。
3. Claude 全部待阅读自然语言输入完整中→英；范围包括首次提问、追问、纠正、必要历史、附件、OCR、检索及工具上下文。英文输出与必要澄清完整英→中，用户补充再按输入规则处理。完整译文与摘要分别标记；摘要仅导航，不能绕过全文要求。
4. 保护代码、命令、路径、公式、标识符、数据和必要原文引文；保留原始字节、来源和映射。全英文工作视图不得破坏执行语义或证据真实性。实质歧义、关键 OCR 或缺块问题中文澄清，未解决时停止依赖其含义的操作。
5. GPT 零强制翻译、无强制双语副本，原语言直接处理，默认中文回答；用户明确要求翻译时按任务执行。B 的执行职责继续存在。路由依实际且已验证的模型族，每轮固定快照；身份未知/不匹配停止，执行中身份变更先暂停再建新版本，不静默换 A。
6. **A 必须亲自产出或完整输出最后采用的完整英文定稿。** 默认 `require_a_authored_canonical=true`。B 可以提供材料/草稿，但 B 写全文、A 仅返回 PASS 的文件不得称 A 原件。截断响应不得作为定稿。捕获真实 A 请求、模型、会话、轮次与完整正文；哈希只证明字节未变，不能单独证明作者身份。A 的必要输出成本计入预算。
7. **双语文件必须同源版本配对交付。** 英文原件不可变，中文译文逐块对应；按请求格式渲染两份完整文件并检查字体、表格、公式、链接及高风险页。作者、定稿者、审核者、渲染者分别记录。完整检查通过后原子发布；任一文件实质变更使相关译文、排版、QA 和批准失效。禁止半包、跨版本文件和不完整下载清单冒称完成。
8. 主聊天只展示用户原问题、批准最终回答、必要中文错误/澄清及附件入口。内部翻译、A/B 交接、提示词、工具/验证日志和内部英文输出在服务端投影前阻断，不靠 CSS 隐藏，不先发英文再撤回。PublicEvent 只允许 `message.accepted`、`response.pending`、`answer.published`、`artifacts.published`、`request.failed`、`request.cancelled`、`input.required`，其中 pending 仅驱动普通等待。
9. 真实失败不得伪装成功。进程退出码 0、B 自称完成、translated=true、机械检查通过或 A 自评分都不能单独触发发布。缺成果、证据、来源、译文、渲染或批准时阻塞相关成功事件；取消后不发布迟到回答、不启动新模型请求。
10. 用量和证据须可核对，涵盖失败、重试、返修、取消、升级 A、翻译修复及接管；请求去重，累计量正确差分，缓存/推理子项不重复计数。真实报告、估算与未知分开，未知不填零。fake 结果仅证明对应测试场景，不能证明真实接入或完整产品通过。

规则来源：主计划第 18–30、89–109、210–234、396–406 行；翻译规格第 7–138 行；质量计划第 14–20、67–80、240–247 行。规则详细位置和 R 编号映射见 JSON `hard_constraints`。

## 验收与发布

R01–R15 的逐项验收定义、验收责任角色、来源和预定证据位于 `requirements-v1.json`。所有 `product_validation_status` 为 `not_verified`。D001 只验收可追踪的文档基线，不能据此将产品需求标通过。

软件功能发布须满足真实连接、四类任务真实样例、语言/来源/界面边界、恢复与隔离、用量核对、签名更新/回滚、备份恢复及本地 SLO 门槛。优化配置另须在具体模型/领域/难度上同时证明质量目标和 A 用量改善；证据不足回到 A 主导配置，不声称等效或节省，也不把统计证据不足当作软件已失败。

单个翻译作业最多 3 次候选（初次 + 2 次定点修复），连接重试单独计数最多 3 次且先确认上次状态。B 自主质量返修初始参数为最多三轮，同缺陷两轮无进展升级 A；这些是版本化运行参数，不是 A 推理/验收投入的武断上限。预算耗尽保存检查点、停止新请求，不降低验收。

## 优先级与变更

当前用户实施授权优先于历史计划编写轮次说明。主计划定义总体范围，翻译规格细化语言/界面/文件来源，质量计划定义测量和发布资格，基础手册细化当前执行顺序。原工作流冲突处按主计划与专门规格处理；具体决策见 `decision-log.md`。

后续任何实质需求、非目标、硬约束、验收定义或责任变更必须升版，保留 v1 和来源快照，登记授权依据、理由、差异、角色复核及受影响任务/验收。不得原地改弱质量或 A 完整英文定稿规则。未获新授权的范围变更保持未决，仅阻塞依赖该变更的工作。
