1. **P1 — D039 is not assembled into the normal runtime.** `services/orchestrator/app/runtime/native_executor.py:65` stages only report formats, without `extra_artifact_ids`. `services/orchestrator/app/profiles/registry.py:8` exposes only code/paper/document. A production-source search finds `CompositePipeline` only at its declaration in `documents/composite.py:75`, with no runtime caller. Trigger: submit the monthly CSV task through the actual API/supervisor path. Impact: the declared data→code→computed results→chart→report chain and original CSV/code/chart delivery are absent, although `tests/integration/test_composite_workflow.py:34` manually runs the pipeline and `:67` manually supplies extras. Fix: add and assemble the composite contract/profile and its verified computation, dependencies, validator and required attachment publication through the native entry point; test submit→planner→executor→bundle, retaining fake-only external model responses.

2. **P1 — strict profiles cannot pass the native C validator.** `services/orchestrator/app/runtime/native_validation.py:30` accepts only `C_METHOD:<registered method>`, while `services/orchestrator/app/profiles/document.yaml:34` requires `source_completeness` and `profiles/registry.py:38` strictly pins profile conditions. Trigger: a contract faithfully containing the document profile acceptance criteria. Reproduced by validating that contract with `validate_profile_contract`, then invoking the actual `NativeRegistryValidator`: both `document.C1` and `document.C2` return `passed=false`, `MECHANICAL_METHOD_UNAVAILABLE`. Paper and code have the same mismatch. Impact: valid profiled tasks block; replacing the conditions with native names instead fails profile validation. Fix: assemble real verifiers for each exact profile condition, with evidence proving the condition rather than aliases that silently weaken it.

3. **P1 — cancellation after a translation response erases reported cost.** `services/orchestrator/app/translation/service.py:118` applies the post-await route fence before `:121` records usage. Trigger: the external translator finishes with reported usage while cancellation is recorded during `await port.invoke`. Reproduced with the real service/SQLite and a fake response reporting 12 input + 12 output tokens: `ROUTE_INVALIDATED_OR_CANCELLED`, **zero usage entries**, and the issued translation call remains `pending`. Impact: consumed B translation tokens disappear from D029/D037 accounting and recovery cannot distinguish the received response from an unresolved call. Fix: persist cost/receipt independently of publication eligibility, then enforce cancellation and identity fences; retain failed/cancelled response status and prevent public publication.

4. **P2 — the PDF completeness gate accepts a missing repeated block.** `services/orchestrator/app/documents/render.py:332` tests each expected block with a separate substring membership check at `:334`. Trigger: the source contains two identical required paragraphs, but rendered PDF has only one. Reproduced using actual `DocumentRenderer` PDF bytes: source has 3 blocks (heading + duplicate paragraphs), PDF model has 2; `verify_pdf(pdf, full_model)` returns `status=pass`. Impact: publisher byte verification can approve an incomplete PDF or DOCX preview because one occurrence satisfies multiple source blocks. Fix: verify ordered, non-overlapping occurrences / an explicit block-to-page map with multiplicity, and reject missing or reordered blocks.

5. **P2 — ordered and nested lists silently lose structure.** `services/orchestrator/app/documents/parse.py:55` stores every list item as a flat `list_item` without list type/start/depth; `documents/render.py:195` emits every item as a top-level `-`, while `:201` compares only kind/content. Trigger: `1. First action.\n2. Second action.\n   - Required child step.\n`. Actual render becomes three top-level bullet paragraphs and reports `status=pass`. DOCX uses `List Bullet` at `:292`; PDF renders ordinary paragraph text. Impact: numbered instructions and substep relationships change in a supposedly complete document. Fix: preserve and compare list structure metadata across parsing, translation and all requested render formats, or explicitly block unsupported list structure instead of declaring completeness.

6. **P2 — installing the initial glossary does not invalidate old default-cache entries.** `services/orchestrator/app/translation/service.py:148` keys only the glossary version label, then loads task-local entries at `:173`; `translation/glossary.py:15` can install version `1` after translations previously used an absent default `1`. Trigger: translate without a stored glossary, install the first domain glossary as version `1`, then explicitly retry the same source/context. Reproduced: initial fake translation of 岸 is `bank`; install geography v1 mapping 岸→`shore`; retry returns `bank`, `cache_hit=true`, translator calls remain 1. Impact: cached READY translation ignores the active domain sense. Fix: pin a glossary content/domain/task digest (including the absent-glossary state) in job/cache identity, or forbid version reuse and invalidate affected entries on initial glossary installation. Task-local labels also need isolation when an explicit context hash is shared.
