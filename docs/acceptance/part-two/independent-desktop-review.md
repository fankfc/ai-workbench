1. **P2 — a backend disconnect clears approved answers and files already on screen.** `apps/desktop/src/renderer/App.tsx:51` empties `publicState` and `bundles` whenever the effect's `backend.state` dependency changes, before `:52` checks readiness. Trigger: finish a conversation, then stop or lose the managed backend. Actual Electron reproduction: two displayed messages become zero while the route remains the same conversation. The same unconditional reset drops loaded file cards. Impact: an offline user loses access to already displayed local results; this contradicts D021's explicit requirement to retain existing messages during disconnect. Fix: reset conversation state only when conversation identity changes; on disconnect, retain approved messages/bundles/draft and change connection status/subscription behavior. Reconnect should merge/reload the same conversation safely.

2. **P2 — a late submit receipt changes a completed task back to pending.** `apps/desktop/src/renderer/App.tsx:83` unconditionally writes `status:'pending'` after awaiting `submitTurn`, overwriting a run already completed by public polling. Trigger: the public approved answer arrives before the submit IPC promise resolves. Reproduced by delaying only the authenticated submit handler's return by 2.5 seconds after the real backend accepted it: two approved answers are visible, yet one “正在准备回答…” notice persists and the next send is disabled. Reload recovers, confirming stale renderer state rather than an unfinished backend task. Impact: successful work appears unfinished and the conversation cannot continue normally. Fix: preserve an existing run's event-derived status/attempt identity; insert a receipt placeholder only if this turn has no newer public state. Apply the same monotonic rule to failure/cancellation/needs-input terminal states.

3. **P2 — an old submit continuation injects its run into the newly selected conversation.** `apps/desktop/src/renderer/App.tsx:81` captures `conversationId`, but `:83` updates the global active page state without checking that identity after the asynchronous call. Trigger: send in a conversation, then navigate to a new or different conversation before its submit receipt returns. Actual Electron reproduction under the same bounded return delay: current route is `#/chat/new`, displayed messages are zero, but an old task's preparing notice appears and the new draft's send is disabled. Impact: an unrelated conversation is blocked by an invisible old task, and its stop button targets that old task. Fix: keep results keyed by captured conversation identity (or fence all async chat continuations with an active conversation generation); only mutate the visible conversation if it still owns the operation. Attachment import/removal and cancellation continuations should use the same ownership rule.

4. **P2 — date filters use UTC calendar days instead of the user's local days, and omit the final fractional second.** `apps/desktop/src/renderer/settings/Usage.tsx:7` concatenates `T00:00:00Z` and `T23:59:59Z` onto the chosen date. Captured actual `getUsage` IPC inputs in an Asia/Shanghai Electron session for 2026-10-14 are `2026-10-14T00:00:00Z` through `2026-10-14T23:59:59Z`, which represent local October 14 08:00 through October 15 07:59:59. Impact: local midnight–08:00 usage is omitted while the following day's early usage is included. With the API's inclusive end comparison (`services/orchestrator/app/api/usage.py:46`), entries after `23:59:59.000` within that UTC day are also excluded. Fix: derive local midnight boundaries from the selected calendar dates, serialize normalized UTC instants consistent with stored timestamps, and use exclusive next-day midnight or a supported inclusive millisecond endpoint. Test both non-UTC offsets and the day's final fractional second.
