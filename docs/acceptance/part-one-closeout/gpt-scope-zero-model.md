# Actual zero-model native scope metadata validation

The corrected pinned official app-server probe completed in 1.206 seconds with two metadata service launches and zero submitted model turns. It performed a private baseline `config/read`, then launched a separately restricted service with per-process overrides and read its actual effective configuration. All 21 required controls were explicitly verified from returned values; they were not inferred from argv.

The baseline contained one configured MCP server. The restricted effective key set exactly matched the baseline set, and the returned server had explicit `enabled=false`. Only counts and aggregate verification booleans were exported. The raw configuration, MCP names, private argv, transport fields, environment fields, account/auth data, and stderr bodies were not exported. No HOME/config/auth file was directly read by the helper; the official CLI handled its existing configuration and authentication privately.

The verified controls cover disabled shell and image viewing, ordinary and exclusive Code Mode, both typed Code Mode host members, multi-agent features, apps/plugins/tool suggestion/recommendation, memory tools and memory use, cloud skills, image generation, web search, hooks, deferred environment handling, permission requests, and an empty legacy notify array. The compiled Code Mode fallback field is not directly exposed as a compiled RPC field: its **explicit typed effective configuration member** was verified false, and the version-pinned source maps that member to the compiled value. No default-value or bare-feature-bool inference is needed.

An actual `thread/start` created the owned ephemeral thread with `environments=[]`, `dynamicTools=[]`, read-only sandbox, disabled network access, and approval policy `never`. The returned metadata confirmed empty environments, ephemeral state, and the strict policy. An owned `thread/read` independently returned the same ID and empty environments; no turns were returned. `thread/unsubscribe` was acknowledged. No generation method was allowed by the helper, no model activity notification or client callback was observed, and all services were cleaned by the Windows Job manager. Processes, temporary directories, open handles, active child processes, and failed cleanups ended at zero. Local service cleanup does not claim a confirmed remote stop.

Two earlier zero-model failures remain preserved. Their restricted services exited before initialization while the baseline queries succeeded. The private error bodies were not exported. Source inspection established a concrete override syntax defect: the CLI splits dotted paths literally, so a quoted MCP path segment becomes an unintended literal quoted key. The corrected helper sends one top-level inline TOML table containing the actual private server keys and only `{enabled=false}`. This preserves the original CLI-managed transport/auth fields without copying them. Structured feature merging also requires explicit Code Mode host members; changing only a scalar feature flag can retain an old fallback member. The corrected effective response confirmed both required typed members false.

The projector first produced four business RED failures and one pass, then five GREEN cases. The override correction had one business RED and seven passes, then eight GREEN cases, including quoted/dotted/Unicode names, missing controls, incorrect ownership, nonempty environments, and private canaries. Read-only evidence verification passed all 13 checks. Across all three preserved attempts there were six metadata service launches and zero model submissions. The earlier continuation budget remains sealed at 2/2 and the independent SSE budget at 1/1.

This establishes **actual metadata preconditions for a constrained native tool boundary**, not production execution scope. It does not inspect the model-facing registry of a real request, test forbidden filesystem/tool calls during a model execution, bind this policy to a production workflow invocation, or prove that configuration refresh cannot change the MCP boundary during a request. The fixed helper exposes only initialize/config-read/owned-thread-start/read/unsubscribe methods and rejects server callbacks, but the native refresh lifetime still needs source and runtime validation. `scope_enforced`, `runtime_scope_qualification`, and `production_enabled` therefore remain false. The successful earlier SSE identity observation belongs to a separate execution and is not retrospectively qualified by this metadata probe.

The independent bounded lifetime source check found concrete trusted-client mutation/refresh paths: [configuration processor](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/request_processors/config_processor.rs#L356) reloads the latest layers and refreshes active threads after explicit config batch-write or experimental-feature mutation; plugin installation can request the same reload, and explicit MCP server refresh reloads MCP configuration. The inspected SkillsWatcher only clears skill caches and emits `SkillsChanged`, and the inspected filesystem watcher emits path notifications. No automatic MCP reload was found in those checked watchers. This is a bounded finding, not a complete repository caller closure: the lifetime remains unknown, and the report does not assert that only the private client can ever cause refresh. The probe's fixed methods exclude all the identified mutation/refresh entries.

A second independent lane reviewed the actual receipts, private projection, method guard, cleanup and current hashes without running CLI/model/test helpers. It confirmed the 21 returned-value checks, exact MCP set, two typed host booleans, owned empty environments, zero-generation guard, preservation of both failed helper snapshots, and all six local cleanups. It explicitly treated `dynamicTools=[]` as a submitted restriction rather than proof of a model-facing registry.
