## Boundaries already supported by source evidence

The worker returns method-not-found (`-32601`) for unsupported client callbacks without fabricated result/authentication material. It exports only the callback method category and fixed error code rather than original params. Provider frames are wrapped before parent processing, so a provider cannot forge the worker's own started/cleanup signals merely by naming a nativeRpc method. Worker stderr contents are discarded; byte counts are exported. Account reports select logged-in/type only, and model catalogs omit arbitrary credential fields.

Configured Codex thread model and ZCode catalog/current selection remain explicitly distinct from actual per-turn execution identity. Both metadata wrappers keep actual_model_id=None, identity_status=unknown, scope_enforced=False and production_enabled=False. No method-only/catalog observation provides the capability needed by PhaseBridge or Workflow. Unsupported authorization/runtime-header/permission/browser callbacks stay unavailable; the connector does not access secret stores to synthesize them.

ProcessManager creates its worker with the Job Object in the creation attribute list (PROC_THREAD_ATTRIBUTE_JOB_LIST), then verifies Job membership before resume. The helper's provider child is created inside that Job without breakaway, so descendants inherit the managed tree. Handles are restricted to standard IO and the manager's environment is an explicit allowlist. Job membership/lifetime cleanup does not establish file scope or remote cancellation; reported remote state stays unknown. Existing author tests already cover tree cleanup, bounded output and honest callbacks; this reviewer did not repeat those tests.
