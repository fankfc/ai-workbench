# D019 four-domain mechanical registry

The registry binds every result to an acceptance criterion, exact artifact revision and actual file SHA, records its method/environment/duration, and writes a real evidence JSON with hash. With a database supplied it additionally requires the current persisted D016 revision. Scope, immutable BlobStore paths, byte changes during checking, unknown exits, not-executed results, missing tools, timeouts and truncation fail closed. Mechanical results do not replace semantic or manual review.

Code fixtures execute real native Python through D011 Windows Job containment and verify both success and exit 7. Generated tests alone cannot establish execution. No arbitrary model code is enabled without a verified OS sandbox; the executed fixtures are explicitly service-authored and test-only.

Paper checks validate citation numbering/definitions, recompute sums from finite Decimal CSV values, and reject undefined citation IDs, absent/corrupt data and mismatching sums. Citation structure remains separate from bibliography authenticity and claim support, which stay `pending_A_review`. The frozen references are labelled fixtures and do not claim to be scientific sources.

Document checks read actual UTF-8 or DOCX ZIP/XML bytes and compare protected names, numerical tokens and headings against actual source snapshots. Missing source remains not_verified; absent renderer remains blocked. Renderer exit 0 without a named output fails. Rendering output decoding supports bounded noninterlaced 8-bit RGB/RGBA PNG CRC and pixel-stream verification; it does not establish visual quality or activate an installed renderer. Unsupported output formats remain unverified. Comprehensive layout checking remains a later document capability.

Mixed checks require the real current dependency graph and return its version fence. Stale or absent graph proofs cannot pass. The real SQLite fixture demonstrates current and stale revisions; independent revision behavior is covered by D016.
