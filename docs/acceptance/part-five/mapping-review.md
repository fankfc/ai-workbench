# 阶段五验收映射源码复核

复核者：本轮主代理，非验收装置实现者。依据第五部分原文逐节检查 `quality/work-orders.json` 与 `scripts/phase_five_verify.py`。

十节分别映射单任务派工、开发交接、A规划、B执行、忠实翻译、独立上下文复核、A验收、C固定规则、返修及阻塞交接。映射中的测试在当前源码中具有精确函数或显式参数ID；实际运行后才能获得对应通过观察。

本轮加入语义失败证明被改写、B返修和A接管之前失败证明变化的反例。C规则复用现有身份、版本、依赖、发布、用量和公开投影检查；不因提示词出现就替代固定程序门槛。角色规划概念映射到既有合同字段，原 TaskContract 摘要未改变。

装置只启动本轮新建的回归目录，核对本轮源码、实际命令返回码、原始测试报告和内层封存清单。跳过、重复、失败、缺失、只检查映射和只执行一个lane均不能得到完整阶段五本地通过。最终摘要写入后才创建外层清单，内层清单保持原字节。

`local_status`仅覆盖列出的机械行为，`full_step_accepted`保留false。即使十节所列检查都通过，也不能取得真实供应商、人工、完整产品、签名发布或质量/token优化资格；这些分别保留在机器报告中。完整默认回归另外约束所有本地测试，不能拿所选映射覆盖其余失败。

历史诊断批次保留各自使用的映射和源码哈希；最终批次以自身封存的映射字节为准，不把旧批次记录改写成新版本结果。
