# A 判断与合同升级

合同版本为1.0，四域完整固定样本见 contracts.json。A 的问题建模、核心推理、关键方法、证据充分性和最终语义判断是明确责任。模型调用次数没有固定为两次；预算与实际状态仍限制每次新增调用。

| 已观察条件 | 决策 | 必需依据 |
| --- | --- | --- |
| 实质歧义或缺少用户才能提供的输入 | ask_user / NEED_EVIDENCE | 指出缺少输入及影响的验收项 |
| 证据缺口、假设失败或方法改变 | A_review | 原件、差异、对应验收项与当前版本 |
| 能力不足 | A_takeover | 明确未能完成的步骤和现有证据 |
| 同一问题连续两轮无进展 | A_takeover | 两轮实际反馈和成果差异 |
| 所有强制项具备当前版本证据 | PASS 评估 | A 的结构化判断和真实哈希证据 |
| 仍能按原合同修复 | REPAIR | 具体缺陷及修复目标；最多三轮质量返修 |

升级不采用B自信分数。强制语义项必须由A或人工承担；B不能降低标准、增加预算或重新定义目标。同版本合同摘要不一致时拒绝运行。全文审稿必须有原件读取覆盖清单，声明读过摘要不足以通过。

PASS不会自动发布。发布器另行核验冻结合同、当前成果、A审查、证据字节、版本依赖与取消状态。需要A原件的任务还要求真实A响应来源，B的报告不能因A批准而改署A。

验证命令：项目解释器运行 `-m pytest tests/unit/test_task_contracts.py -q`。40个行为用例的RED/GREEN记录位于本目录；实际产品语义质量仍未通过真实提供方验收。
