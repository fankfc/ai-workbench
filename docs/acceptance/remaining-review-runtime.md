## Findings

1. **HIGH — A pre-publication fake answer event becomes visible after a later valid release.** `services/orchestrator/app/runtime/public_projection.py:66` delegates every answer.published row to `_release_payload` without checking that the triggering event's payload.release_id or event_id identifies the actual publisher's release. In a disposable native fixture, a fake answer row with invented approval remained invisible at READY, then a legitimate NativePublisher.publish made both rows visible: answer count 0→2, same message_id but different SSE event sequence. The fake text did not leak; the approved answer was duplicated. Bind projection to the trusted published event/release record and refuse earlier or unrelated answer rows. Add a test that stages a fake answer before the legitimate publish and then replays history/SSE.

2. **HIGH — A canonical-author claim can contradict the stored artifact.** `services/orchestrator/app/runtime/publication.py:41` evaluates decision fields and then `:46` reads the artifact bytes, but does not compare the contract's require_a_canonical requirement with ArtifactVersion.canonical_issued_by/a_response_ref. A fixture contract requiring A canonical content, decision canonical_author=A and actual artifact canonical_issued_by=B still produced one published answer. Validate provenance from the immutable artifact row, including the A response association, at stage and immediately before publish; decision prose cannot relabel B output as A's original. The probe preserved the valid evidence hashes and current revision, isolating this provenance mismatch.

3. **HIGH — Repeated delta observations with the same provider request/sequence can double count.** `services/orchestrator/app/usage/ledger.py:35` deduplicates only by event_id; `:66` adds every delta regardless of an already observed sequence. Recording the same request, sequence=1 and 30 tokens under two receipt IDs yielded 60 tokens. Treat request/sequence as a second stable observation key: exact repeats should be idempotent and conflicts must fail. Verify out-of-order distinct deltas still count once.

4. **MEDIUM — Starting another attempt removes the already delivered answer from history.** `services/orchestrator/app/runtime/public_projection.py:80` requires the old PUBLISHED attempt still be the latest, and the helper also reads mutable current-revision/dependency state. A published answer present once in history became absent after a new RECEIVED attempt was inserted. The main plan explicitly says historical delivered versions remain viewable. Preserve an immutable public release snapshot authorized at publication time for historical history/SSE, while checking current attempts/revisions for new publication; do not dynamically rewrite or hide the former delivery. The same mutable helper also changes qualified-deliveries denominators in usage summary.
