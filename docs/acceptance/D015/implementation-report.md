# D015 implementation

The persistent request ledger retains raw hashed observations, role, function, domain, attempt, provider and terminal status. Duplicate request bills are idempotent. Request totals, increments and explicitly scoped cumulative session counters have separate rules: 120→200 allocates 200 overall, including across two requests. Cache/reasoning child fields are not double-counted. Missing values remain null and unknown; estimated usage is labeled separately. Failed, cancelled, translated and takeover requests remain counted.

Observed RED: 20 behavioral failures, followed by GREEN. Further invalid-delivery, duplicate provider sequence and pending-mode regressions failed before their fixes. Final card suite: 28 passed. A durable pending observation is reserved before a model starts; the first actual observation can resolve it into request totals, cumulative counters or deltas without losing crash uncertainty. Replaying the original reservation remains idempotent. The budget gate stops before new provider starts on unknown usage, missing estimates or exhausted budgets and protects the remaining A reserve. Monetary cost is unknown until an actual supported report is provided. Tokens per qualified delivery are uncomputable with no approved actual delivery.
